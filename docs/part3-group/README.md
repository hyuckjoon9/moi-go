# Part 3 — 그룹·일정

모집글에 연결된 스터디 그룹과 그룹 홈, 그룹 단위 일정을 담당한다. Part2의 모집 흐름을 그룹으로 연결하고 Part4가 사용할 일정·권한 정책을 제공한다.

## 담당 기능

- 그룹 생성 연동, 내 그룹 목록·그룹 홈 및 활성 구성원 조회
- 일정 생성·목록·상세·수정·삭제와 참석 응답 마감 관리
- Part2 그룹 프로비저닝 및 Part4 참석 응답·그룹 출석률 권한 정책 제공

## 주요 흐름

모집글 게시 → 그룹과 리더 생성 → 지원 승인 → 그룹원 추가 → 그룹 홈·일정 조회 → 운영진의 일정 관리 → 일정 마감 기준에 따라 Part4 참석 응답 처리 → 스터디 종료 시 그룹 종료로 이어진다.

## 제공 API와 내부 계약

- HTTP API는 `/api/groups/me`, `/api/groups/{groupId}`, `/api/groups/{groupId}/schedules`와 일정별 수정·마감·삭제 경로를 제공한다.
- Part2는 `StudyGroupProvisioningPort`로 그룹 생성·멤버 추가·종료를 요청하며, 같은 `postId`의 그룹 생성은 멱등적이다.
- Part4에는 `ScheduleAttendancePolicyReader`로 일정·활성 그룹원·실질 마감을, `StudyGroupAttendanceRatePolicyReader`로 그룹 전체 출석률 조회 권한을 제공한다.

## 핵심 설계 및 처리 기준

- `study_groups.post_id`는 모집글당 그룹 하나를 보장하며, 그룹원 중복은 `(group_id, user_id)`로 막고 탈퇴 이력은 `WITHDRAWN`으로 보존한다.
- 활성 그룹원은 종료 그룹을 포함해 그룹 홈과 일정을 조회할 수 있다. 일정 관리는 활성 그룹의 활성 `LEADER`·`MANAGER`만 할 수 있다.
- 응답 마감은 `responseDeadline` 또는 일정 시작 시각이며, 참석 응답은 실질 마감 이전에만 변경할 수 있다.
- 미래 일정만 삭제할 수 있다. 참석 응답은 함께 삭제되지만 출석·활동 기록이 있으면 삭제를 거부한다.

## 관련 파트

- Part1의 인증 사용자 ID와 공개 회원 계약을 사용한다.
- Part2가 공개 프로비저닝 포트로 그룹 생성·멤버 추가·그룹 종료를 요청한다.
- Part4는 참석 응답 마감과 그룹 전체 출석률 권한을 Part3 포트에 위임하며, 1차 MVP에서는 집계용 일정·활성 그룹원 목록을 직접 조회하는 예외가 있다.
