# 일정 조회 설계

## 목적과 범위

활성 그룹원이 예정·지난 일정 페이지와 일정 상세를 조회한다. 목록은 데이터 누적에도 응답 크기와 순서가 안정적이어야 하며, 상세는 그룹 경계를 보장한다. API 계약은 [`api.md`](api.md)를 따른다.

## 접근과 시간 경계

- 역할과 무관하게 활성 그룹원에게 허용한다.
- 종료 그룹도 조회할 수 있다.
- 그룹 존재 → 그룹원 기록 → 탈퇴 상태를 일정 조회보다 먼저 확인해 비회원에게 일정 존재를 노출하지 않는다.
- 상세는 `scheduleId`와 `groupId`를 함께 조회한다.

목록 기준 시각은 주입된 `Clock`에서 한 번 얻는다. 예정은 `scheduledAt >= now`, 지난 일정은 `scheduledAt < now`이므로 겹침이나 누락이 없다.

## 페이지와 정렬

- 예정: `scheduledAt ASC`, `id ASC`
- 지난 일정: `scheduledAt DESC`, `id DESC`
- 보조 ID 정렬은 같은 시각의 페이지 결과를 안정화한다.
- `SchedulePageResponse`로 Spring Data `Page`를 직접 노출하지 않는다.
- 목록은 요약 필드만, 상세는 기존 `ScheduleResponse` 전체를 반환한다.

Repository는 `(group_id, scheduled_at)` 인덱스를 활용하는 두 범위 조회와 그룹 제한 단건 조회를 제공한다.

## 검증 요점

- 경계 시각의 일정이 예정 목록에 포함된다.
- 범위·주 정렬·보조 정렬·다른 그룹 제외와 페이지 메타데이터를 검증한다.
- 모든 역할과 종료 그룹의 조회, 비회원·탈퇴 회원·다른 그룹 일정 거부를 검증한다.
- `scope`, `page`, `size` 기본값과 잘못된 요청을 검증한다.
