# Part3 그룹·일정 기능 명세

> 이 문서는 기획·프론트엔드·백엔드가 공유하는 사용자 기능과 업무 규칙의 기준이다. HTTP 필드와 예시는 [api.md](api.md)를 참고한다.

## 목적과 범위

Part3는 모집 완료된 스터디의 그룹 홈과 일정을 제공한다. 사용자는 자신이 속한 그룹을 확인하고, 그룹 운영자는 일정을 관리하며, 모든 활성 그룹원은 일정을 조회한다.

| 범위 | 포함 기능 | 제외 기능 |
| --- | --- | --- |
| 그룹 | 그룹 생성 연동, 내 그룹 목록·그룹 홈 조회, 구성원 표시 | 모집 승인 처리, 프로필 정보 관리 |
| 일정 | 생성·목록·상세·수정·삭제, 참석 응답 마감 설정 | 참석 여부 입력·출석 판정·활동 기록 작성 |

## 용어와 상태

| 용어 | 값 | 의미 |
| --- | --- | --- |
| 그룹 상태 | `ACTIVE`, `ENDED` | 운영 중 또는 종료된 그룹 |
| 그룹원 상태 | `ACTIVE`, `WITHDRAWN` | 현재 소속 또는 탈퇴 이력 |
| 그룹 역할 | `LEADER`, `MANAGER`, `MEMBER` | 리더, 운영진, 일반 멤버 |
| 실질 마감 | `responseDeadline` 또는 `scheduledAt` | 응답 마감이 없으면 일정 시작 시각이 마감 |

## 사용자별 권한

| 사용자 | 그룹 홈·일정 조회 | 일정 생성·수정·마감 변경·삭제 |
| --- | --- | --- |
| 활성 `LEADER` | 가능 | 가능. 그룹이 `ACTIVE`인 경우만 |
| 활성 `MANAGER` | 가능 | 가능. 그룹이 `ACTIVE`인 경우만 |
| 활성 `MEMBER` | 가능 | 불가 |
| `WITHDRAWN` 또는 비그룹원 | 불가 | 불가 |

- 종료 그룹도 활성 그룹원은 그룹 홈과 과거·예정 일정 정보를 조회할 수 있다.
- 종료 그룹에서는 어떤 일정 관리 작업도 할 수 없다.
- 다른 그룹의 일정 ID를 주소에 넣어도 일정이 없는 것과 동일하게 처리한다.

## 기획·프론트엔드 기능 흐름

### 내 그룹 목록

1. 사용자는 활성 그룹원으로 속한 활성 그룹만 조회한다.
2. 목록은 최근 가입 그룹부터 표시한다. 가입 시각이 같으면 그룹원 ID가 큰 항목을 먼저 표시한다.
3. 프론트엔드는 `LEADER`, `MANAGER`를 운영 그룹으로, `MEMBER`를 참여 그룹으로 구분한다.

### 그룹 홈

1. 사용자가 그룹 홈에 진입하면 그룹 기본 정보와 활성 구성원을 조회한다.
2. 구성원은 리더, 매니저, 멤버 순서로 표시한다.
3. 구성원의 닉네임·프로필은 이 API 범위에 포함되지 않는다. 필요하면 Part1의 공개 회원 정보 계약을 별도로 연동한다.
4. 내 역할이 `LEADER` 또는 `MANAGER`이고 그룹이 활성 상태일 때만 일정 관리 UI를 노출한다.

### 일정 목록과 상세

1. 기본 목록은 예정 일정(`upcoming`)이며, 가까운 일정부터 표시한다.
2. 지난 일정(`past`)은 최근 일정부터 표시한다.
3. 목록은 페이지 단위로 조회하며 `hasNext`가 참이면 다음 페이지를 요청할 수 있다.
4. 목록에는 제목, 일시, 장소, 온라인 링크, 응답 마감만 표시하고, 내용·준비물은 상세 화면에서 표시한다.

### 일정 생성과 수정

1. 운영자는 미래 일정만 생성할 수 있다.
2. 제목과 일정 시각은 필수다. 장소와 온라인 링크는 동시에 비어 있을 수 있다.
3. 빈 문자열은 저장되지 않고 `null`로 처리된다. 화면에서는 선택 입력을 비워 전송해도 된다.
4. 수정은 부분 수정이 아닌 전체 교체다. 화면은 제목·일시·장소·온라인 링크·내용·준비물을 모두 보낸다.
5. 시작 시각이 지난 일정은 수정할 수 없다.
6. 수정 시 기존 응답 마감은 유지된다. 새 일정 시각이 기존 마감보다 빨라질 수는 없다.

### 응답 마감과 참석 응답

1. 운영자는 일정 생성 때 응답 마감을 설정하거나, 이후 별도 변경할 수 있다.
2. 응답 마감은 일정 시작 시각을 넘길 수 없고 현재보다 미래여야 한다.
3. 별도 마감이 없으면 일정 시작 시각이 실질 마감이다.
4. 현재 시각이 실질 마감보다 엄격히 이전일 때만 참석 응답을 등록·변경·삭제할 수 있다.
5. 이미 마감된 일정의 마감을 연장하거나 재개방할 수 없다.
6. 프론트엔드는 `responseDeadline ?? scheduledAt`을 기준으로 응답 UI를 비활성화하고, 서버의 `ATTENDANCE_RESPONSE_CLOSED` 오류도 동일하게 처리한다.

### 일정 삭제

1. 운영자는 아직 시작하지 않은 미래 일정만 삭제할 수 있다.
2. 참석 응답만 존재하면 일정과 함께 삭제된다.
3. 출석 기록 또는 활동 기록이 하나라도 있으면 삭제할 수 없다.
4. 삭제 성공 시 목록에서 즉시 제거하고, 응답 본문은 기대하지 않는다.

## 백엔드 구현 기준

### 접근 검증 순서

일정 관리 요청은 아래 순서로 검증한다.

1. 그룹 존재 여부
2. 그룹원 기록 존재 여부
3. 그룹원 탈퇴 여부
4. 그룹 종료 여부
5. 리더 또는 매니저 역할 여부
6. 요청 일정의 해당 그룹 소속 여부
7. 작업별 시간·이력 규칙

조회는 4~5단계의 그룹 상태·관리 역할을 검사하지 않는다. 단, 활성 그룹원이어야 한다.

### 데이터와 연동 경계

- 그룹 프로비저닝은 Part2가 `StudyGroupProvisioningPort`를 호출해 요청한다. 게시 시 `createGroup`, 신청 건별 승인 시 `addMember`, 스터디 취소 시 `endGroup`을 사용한다. 기존 일괄 `confirmGroup()` 흐름의 전환은 Part2 작업에서 수행한다.
- `postId`는 그룹 생성의 멱등 키다. 같은 모집글로 재요청해도 기존 그룹과 그룹원을 유지한다.
- Part3는 Part1·Part2의 Entity나 Repository를 직접 조회하지 않고 식별자와 공개 계약만 사용한다.
- 일정 삭제 전 출석·활동 이력은 각 파트의 공개 조회 포트로 확인한다. 최종 데이터 무결성은 FK 정책이 보장한다.
- Part4는 `StudyGroupAttendanceRatePolicyReader#getAttendanceRatePolicy(groupId, requesterId)`로 그룹 전체 출석률 조회 권한을 확인한다. 반환된 `canViewAllAttendanceRates`는 활성 그룹의 활성 `LEADER` 또는 `MANAGER`일 때만 `true`이며, 역할 enum은 Part4에 노출하지 않는다.

## 화면 처리 기준

| 상황 | 권장 처리 |
| --- | --- |
| `UNAUTHORIZED` | 로그인 화면 또는 재인증 흐름으로 이동 |
| `GROUP_ACCESS_DENIED`, `WITHDRAWN_GROUP_MEMBER` | 접근 불가 안내 후 이전 화면으로 이동 |
| `SCHEDULE_MANAGEMENT_FORBIDDEN` | 권한 없음 안내, 관리 화면을 노출하지 않음 |
| `INVALID_SCHEDULE_TIME` | 해당 일시·마감 입력 항목에 검증 메시지 표시 |
| `SCHEDULE_UPDATE_NOT_ALLOWED` | 새로고침 후 읽기 전용 상세 화면 유지 |
| `SCHEDULE_DEADLINE_UPDATE_NOT_ALLOWED` | 마감 변경 UI 비활성화 및 마감 안내 |
| `SCHEDULE_DELETE_NOT_ALLOWED` | 삭제 불가 사유 안내 후 상세 화면 유지 |
| `ATTENDANCE_RESPONSE_CLOSED` | 참석 응답 UI를 닫고 마감 안내 표시 |

## 완료 조건

- 활성 그룹원은 그룹 홈과 일정 목록·상세를 볼 수 있다.
- 운영자만 활성 그룹에서 미래 일정을 관리할 수 있다.
- 일정 수정·삭제·응답 마감의 시간 경계가 서버와 화면에서 동일하게 적용된다.
- API 요청·응답 필드는 `api.md`와 실제 DTO가 일치한다.
