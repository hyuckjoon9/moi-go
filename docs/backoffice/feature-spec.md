# Back Office 기능 명세

> 이 문서는 Back Office 1차 구현 기준이다.
> 세부 구현 경계와 단계는 [architecture.md](architecture.md), HTTP 계약은 [api.md](api.md)를 따른다.

## 목적과 범위

Back Office는 Moi-Go 운영자가 회원, 모집글, 스터디 그룹, 출석·활동 현황을 조회하고 서비스 운영에 필요한 최소 조치를 수행하는 관리자 전용 화면이다. 일반 사용자 화면과 URL 및 API 경계를 분리한다.

1차 구현은 조회, 제한된 운영 조치, 운영 이력 조회까지를 다룬다. 신고 접수, 자동 제재, 통계 분석, 일괄 처리는 포함하지 않는다.

| 구분 | 포함 | 제외 |
| --- | --- | --- |
| 운영 현황 | 회원·모집글·그룹 수와 최근 운영 조치 조회 | 정교한 분석 차트, 데이터 내보내기 |
| 회원 | 목록·상세 조회, 상태 변경 | 회원 정보 임의 수정, 비밀번호 조회·변경 |
| 모집글 | 목록·상세 조회, 노출 숨김·복구 | 내용 대필·수정, 물리 삭제, 운영 종료 |
| 그룹 | 목록·상세·멤버·일정 조회 | 그룹 내용 수정·종료, 멤버 역할 변경 |
| 출석 | 그룹·일정별 출석 요약 조회 | 그룹 역할(`LEADER`/`MANAGER`)의 출석 기록 생성·수정·삭제 |
| 활동 | 활동 기록·리뷰 조회 | 그룹 역할(`LEADER`/`MANAGER`)의 활동 기록 생성·수정·삭제, 그룹원의 리뷰 작성·삭제 |
| 운영 이력 | 관리자 조치 이력 조회 | 이력 수정·삭제 |

## 용어와 권한

| 용어 | 의미 |
| --- | --- |
| 일반 회원 | 시스템 역할이 `USER`인 회원 |
| 운영자 | 시스템 역할이 `ADMIN`인 회원 |
| 그룹 역할 | `LEADER`, `MANAGER`, `MEMBER`처럼 스터디 안에서만 유효한 역할. 시스템 역할과 구분한다. `LEADER`와 `MANAGER`는 출석 체크·활동 기록 관리에서 동일한 권한을 갖는다. |
| 운영 조치 | 회원 정지·해제, 모집글 숨김·복구처럼 서비스 상태를 바꾸는 관리자 행위 |
| 운영 이력 | 운영자, 대상, 사유, 변경 전후 상태, 처리 시각을 보존한 기록 |

- Back Office 정적 HTML은 먼저 로드될 수 있지만, 메뉴와 데이터는 인증된 `ADMIN`에게만 표시한다.
- 클라이언트에서 메뉴나 버튼을 숨기는 것과 별개로 서버가 모든 관리자 API의 역할을 검증한다.
- `USER`가 관리자 API를 호출하면 `403 Forbidden`, 로그인하지 않은 사용자가 호출하면 `401 Unauthorized`를 반환한다.
- 운영 조치 요청에는 공백이 아닌 사유를 필수로 받는다.
- 관리자 계정은 DB 운영 절차로만 생성하며 Back Office에서 생성하거나 승격하지 않는다.

## 기능 명세

### 1. 운영 현황

운영자는 한 화면에서 다음 요약을 확인한다.

- 전체 회원 수, 활성 회원 수, 정지 회원 수, 탈퇴 회원 수
- 모집 중·마감·진행·종료 상태별 모집글 수
- 활성·종료 그룹 수
- 최근 운영 조치 10건

집계 값은 화면 진입 또는 새로고침 시 조회한다. 실시간 스트리밍은 지원하지 않는다.

### 2. 회원 관리

#### 목록·상세 조회

- 이메일, 닉네임으로 검색할 수 있다.
- 역할(`USER`, `ADMIN`)과 상태(`ACTIVE`, `SUSPENDED`, `WITHDRAWN`)로 필터링할 수 있다.
- 목록은 생성일 내림차순을 기본으로 페이지네이션한다.
- 상세에서는 프로필, 역할, 상태, 가입·수정 시각, 참여 그룹 요약, 최근 운영 조치를 조회한다.
- 비밀번호, refresh token, JWT secret 등 인증 비밀값은 어떤 응답에도 포함하지 않는다.

#### 회원 상태 변경

- 운영자는 일반 회원의 상태를 `ACTIVE` 또는 `SUSPENDED`로 변경할 수 있다.
- 상태 변경은 대상 회원의 로그인 가능 여부에 즉시 반영한다.
- 자기 자신의 상태는 변경할 수 없다.
- `ADMIN` 계정은 Back Office API로 상태를 변경하지 않는다.
- `WITHDRAWN`은 사용자의 자진 탈퇴 이력으로 보존하며 운영 제재에 사용하지 않는다.
- `SUSPENDED` 회원은 로그인·토큰 재발급과 인증 API 접근이 차단된다.
- 정지 시 대상 회원의 refresh token을 모두 폐기하고, 해제 후에는 다시 로그인하게 한다.
- 이미 요청한 상태라면 현재 상세를 성공으로 반환하고 운영 이력을 중복 생성하지 않는다.

### 3. 모집글 관리

#### 목록·상세 조회

- 제목, 작성자 닉네임·이메일·ID로 검색할 수 있다.
- 카테고리, 모집 상태, 노출 상태로 필터링할 수 있다.
- 목록은 생성일 내림차순을 기본으로 페이지네이션한다.
- 상세에서는 모집글 내용, 작성자, 모집 상태, 노출 상태, 연결 그룹 ID를 조회한다.

#### 노출 숨김·복구

- 운영자는 부적절한 모집글을 사용자 목록과 상세 화면에서 숨길 수 있다.
- 숨김은 모집 상태(`RECRUITING`, `CLOSED`, `ACTIVE`, `ENDED`)를 변경하지 않는다.
- 숨긴 모집글을 다시 노출할 수 있다.
- 모집 상태와 독립된 `VISIBLE`, `HIDDEN` 노출 상태를 추가한다.
- 모집글과 연결 그룹·지원 이력을 보존하기 위해 운영자 물리 삭제는 제공하지 않는다.
- `HIDDEN` 모집글은 작성자를 포함한 일반 사용자 목록과 상세에서 노출하지 않고 신규 지원을 차단한다.
- 기존 지원서, 연결 그룹, 일정, 출석, 활동 기록은 유지한다.
- 숨긴 모집글은 최근 숨김 순으로 조회하고 제목·작성자·기간으로 검색한다. 모집글 ID 검색은 보조 수단으로 제공한다.
- 이미 요청한 노출 상태라면 현재 상세를 성공으로 반환하고 운영 이력을 중복 생성하지 않는다.

### 4. 스터디 그룹 관리

#### 목록·상세 조회

- 그룹명, 연결 모집글 ID, 리더 회원 ID로 검색할 수 있다.
- 그룹 상태(`ACTIVE`, `ENDED`)로 필터링할 수 있다.
- 상세에서는 그룹 기본 정보, 리더와 멤버, 일정 목록을 조회한다.
- 탈퇴한 그룹원도 운영 확인을 위해 상태와 함께 조회할 수 있다.

### 5. 출석 현황 조회

- 운영자는 그룹의 일정 목록에서 특정 일정을 선택해 출석 요약을 조회한다.
- 요약에는 전체 기록 수와 `PRESENT`, `LATE`, `ABSENT`, `EXCUSED`별 인원 수, 회원별 상태를 포함한다.
- Back Office는 사실 확인을 위한 조회만 제공하고 출석 기록을 생성·수정·삭제하지 않는다.
- 출석 기록 정정이 필요하면 별도의 승인·이력 정책을 먼저 합의한 뒤 후속 기능으로 다룬다.

### 6. 활동 기록·리뷰 조회

- 운영자는 그룹 일정에 등록된 활동 기록(주제, 내용, 과제, 참고 링크)과 그 기록에 달린 리뷰(코멘트) 목록을 조회한다.
- Back Office는 사실 확인을 위한 조회만 제공한다. 활동 기록 생성·수정·삭제는 그룹 역할(`LEADER`/`MANAGER`)의 권한으로, 리뷰 작성·삭제는 그룹원 본인의 권한으로 남는다.
- 활동 리뷰 숨김·삭제는 1차 범위에서 제외하고 조회만 제공한다.

### 7. 운영 이력

다음 운영 조치는 성공한 경우 반드시 이력을 남긴다.

- 회원 상태 변경
- 모집글 숨김·복구

운영 이력에는 다음 값을 보존한다.

| 항목 | 설명 |
| --- | --- |
| 운영자 | 조치를 수행한 관리자 회원 ID |
| 작업 | `MEMBER_STATUS_CHANGED`, `RECRUITMENT_HIDDEN`, `RECRUITMENT_RESTORED` 중 하나 |
| 대상 | 대상 종류와 대상 ID |
| 대상 표시명 | 조치 당시 회원 닉네임 또는 모집글 제목 |
| 변경 내용 | 변경 전 값과 변경 후 값 |
| 사유 | 운영자가 입력한 조치 사유 |
| 처리 시각 | 서버가 기록한 시각 |

- 이력은 관리자도 수정하거나 삭제할 수 없다.
- 이력 조회는 작업 종류, 대상 종류·ID, 운영자 ID, 기간으로 필터링할 수 있다.
- 사유는 앞뒤 공백을 제거한 5~500자로 저장한다.
- 변경 전후에는 상태값만 저장하고 이메일, 게시글 본문 같은 개인정보와 콘텐츠를 복제하지 않는다.
- 1차 구현에서는 운영 이력 보존 기간과 자동 삭제 정책을 정의하지 않는다.

## 화면 처리 기준

| 상황 | 처리 |
| --- | --- |
| 인증 없음 | 로그인 화면으로 이동 |
| `USER` 접근 | 권한 없음 화면을 표시하고 관리자 데이터를 요청하지 않음 |
| 대상 없음 | 목록을 새로고침하고 대상이 이미 삭제되거나 변경됐음을 안내 |
| 상태 충돌 | 최신 상세 정보를 다시 조회하고 중복 조치를 막음 |
| 사유 누락 | 요청하지 않고 입력란에 검증 메시지 표시 |
| 서버 오류 | 사용자가 입력한 사유를 유지하고 재시도 안내 |

## 1차 구현 결정

| 항목 | 결정 |
| --- | --- |
| 회원 제재 | 자진 탈퇴 `WITHDRAWN`과 분리된 `SUSPENDED`를 사용한다. |
| 관리자 계정 | Back Office 상태 변경 대상에서 제외한다. |
| 모집글 노출 | 모집 상태와 별도의 `VISIBLE`, `HIDDEN` 값을 둔다. |
| 운영 종료 | 모집글·그룹 강제 종료는 1차 범위에서 제외한다. |
| 운영 이력 | 생성 후 수정·삭제하지 않으며 대상 표시명과 전후 상태를 보존한다. 보존 기간은 정하지 않는다. |
| 활동 리뷰 조치 | 1차 범위에서 제외하고 조회만 제공한다. |
