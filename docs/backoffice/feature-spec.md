# Back Office 기능 기준

Back Office는 `ADMIN`이 서비스 현황을 확인하고 회원 상태를 관리하는 운영 콘솔이다. 정적
화면의 접근 허용 여부와 관계없이 관리자 데이터와 조치는 서버의 `/api/admin/**` 권한 검사를
통과해야 한다.

## 현재 제공 기능

### 운영 현황

- 회원·모집글·스터디 그룹의 상태별 건수와 최근 운영 조치 최대 10건을 조회한다.
- 집계는 화면 진입 또는 새로고침 때 조회한다. 실시간 스트리밍이나 데이터 내보내기는 제공하지
  않는다.

### 회원 관리

- 이메일 또는 닉네임, 시스템 역할(`USER`, `ADMIN`), 상태로 목록을 필터링한다.
- 관리자 계정은 항상 목록 상단에 표시하고, 각 역할 안에서는 회원 ID 오름차순으로 표시한다.
- 상세에는 기본 프로필, 역할·상태, 가입 시각, 참여 그룹 요약, 최근 운영 조치를 표시한다.
- 최근 운영 조치는 내부 enum 대신 사람이 읽을 수 있는 조치명과 처리 시각·사유를 표시한다.
- `USER`만 `ACTIVE`와 `SUSPENDED` 사이에서 상태를 변경할 수 있다. `ADMIN`, `WITHDRAWN`,
  자기 자신의 상태는 변경할 수 없다.
- 상태 변경 사유는 공백 제거 후 5~500자이며, 실제 변경일 때만 이력을 남긴다. 정지 시 refresh
  token을 폐기한다.

### 모집글 관리

- 제목 또는 모집장 닉네임으로 모집글을 검색하고, 모집 상태와 노출 상태를 함께 필터링한다.
- 상세에는 모집글 내용·모집 조건·모집장·모집 상태·노출 상태·연결 그룹과 최근 운영 조치를 표시한다.
- 관리자는 사유를 입력해 `VISIBLE`과 `HIDDEN` 사이에서 노출 상태를 변경한다.
- 실제 변경만 `RECRUITMENT_HIDDEN` 또는 `RECRUITMENT_RESTORED` 운영 이력으로 보존한다.

### 그룹 운영 조회

- 그룹 이름·상태로 그룹과 활성 인원 수를 읽기 전용으로 조회한다.
- 그룹 이름 또는 일정 제목으로 일정, 출석 대상 회원으로 출석 기록, 활동 주제로 활동 기록을 조회한다.
- 이 화면은 상태 변경·삭제·내보내기를 제공하지 않는다.

### 운영 이력

- 조치 유형, 대상 유형, 대상 표시명 또는 사유로 운영 이력을 검색한다.
- 이력은 최신 처리 시각과 ID 순으로 페이지 조회하며 수정하거나 삭제하지 않는다.

### 화면 공통 기준

- 운영 콘솔은 `/backoffice/index.html`의 단일 화면 안에서 대시보드, 관리, 읽기 전용 조회 뷰를 전환한다.
- 사이드바와 본문, 헤더와 워크스페이스, 뷰 내부 요소는 공통 반응형 여백 토큰을 사용한다.
- 알림 드롭다운은 불투명한 테마 배경을 사용하고, 아이콘은 테마 글자색을 따르는 단색 아이콘을
  사용한다.

## 아직 제공하지 않는 기능

- 스터디 그룹·일정·출석·활동 기록의 관리자 상태 변경 또는 삭제
- 리뷰의 관리자 조회·조치, 신고 처리, 일괄 조치, 자동 제재, 데이터 내보내기

## 보안과 데이터 보존

- 인증되지 않은 관리자 API 요청은 `401`, `ADMIN`이 아닌 인증 사용자의 요청은 `403`이다.
- 비밀번호, refresh token, JWT 등 인증 비밀값은 어떤 관리자 응답에도 포함하지 않는다.
- 운영 이력은 운영자·대상·변경 전후 상태·사유·처리 시각을 보존하며 수정하거나 삭제하지 않는다.
  대상 표시명에는 닉네임 또는 모집글 제목만 저장한다.
