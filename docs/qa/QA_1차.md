# QA 후속 작업 정리

작성일: 2026-07-23

프론트 프로토타입 QA 중 확인된 내용을 프론트 수정, 백엔드 수정, 정책 결정 항목으로 나누어 정리한다.

## 프론트 수정 필요

- 그룹 홈에서 `모집글 작성` 클릭 시 바로 작성 다이얼로그가 열리도록 수정한다.
  - 현재는 모집글 탭으로 이동되는 흐름이 섞여 있어 사용자가 한 번 더 조작해야 한다.
- 모집글 상세 화면에서 계정 전환 후 버튼 상태가 이전 계정 기준으로 남는 문제를 수정한다.
  - 작성자가 아닌 계정은 `참가 신청` 버튼이 보여야 한다.
  - 작성자 전용 버튼인 수정, 삭제, 모집 종료, 활동 종료, 신청자 관리는 작성자에게만 보여야 한다.
- 모집글 수정, 종료, 승인, 일정 조회 등 액션별 성공 메시지를 정확히 분리한다.
  - 모집 종료를 눌렀는데 `일정을 조회했습니다`가 뜨는 문제 수정.
  - 승인 후 `일정을 조회했습니다`가 뜨는 문제 수정.
  - 모집글 수정 후 `모집글 상세를 조회했습니다`가 뜨는 문제 수정.
- 모집 종료 후 화면 상태가 즉시 갱신되도록 수정한다.
  - 종료 후에도 `모집 중`으로 보이는 문제 수정.
- 모집글 작성 성공 후 모집글 목록을 자동으로 다시 불러오도록 수정한다.
- 모집글 상세에서 작성자 본인에게는 `참가 신청` 버튼을 숨긴다.
  - 대신 작성자용 신청자 관리, 모집 종료, 수정 버튼을 보여준다.
- 그룹 홈에서 활성 그룹원은 별도 박스가 아니라 요약 카드의 토글 영역으로 보여준다.
  - 닉네임과 프로필 이미지 중심으로 표시한다.
  - `회원 #3`처럼 내부 ID를 사용자에게 직접 노출하지 않는다.
- 일정 관리는 일정 제목과 날짜 기준으로 선택할 수 있게 한다.
  - 사용자가 일정 ID를 직접 입력하거나 관리하지 않도록 한다.
- 일정 목록은 최신 일정이 위로 오도록 정렬한다.
- 일정 생성 후 일정 목록을 자동으로 다시 조회한다.
- 참석 응답과 출석 체크 결과 JSON을 화면에 그대로 출력하지 않는다.
  - 사용자에게는 성공/실패 메시지와 갱신된 현황만 보여준다.
- 일반 MEMBER 화면에서는 관리 기능을 숨기고 본인에게 필요한 정보만 보여준다.
  - 본인 참석 응답
  - 본인 출석률
  - 그룹 일정 조회

## 백엔드 수정 필요

### Part1 회원·인증

- 프로필 이미지 업로드 및 프로필 이미지 URL 저장 기능은 완료된 상태다.
- 로그아웃 시 DB 재생성 등으로 회원 또는 토큰 정보가 꼬인 경우에도 프론트가 로컬 토큰을 정리할 수 있도록 응답 정책을 확인한다.
- `WITHDRAWN` 회원의 로그인, 토큰 재발급, 내 정보 조회 제한이 일관적으로 동작하는지 확인한다.

### Part2 모집·참가 신청

- 모집 마감일은 오늘 이후 날짜만 허용하도록 검증한다.
- 모집글 삭제를 허용할지, 모집 종료만 허용할지 정책을 확정하고 API 동작을 맞춘다.
- 모집글 상세 응답에 현재 사용자 기준 권한 판단 필드를 포함한다.
  - `leaderId`
  - `isOwner`
  - `isJoined`
  - `canApply`
  - `canManage`
- 모집글 상세 응답에 상세 필드를 빠짐없이 포함한다.
  - `description`
  - `goal`
  - `method`
  - `meetingType`
  - `location`
  - `onlineLink`
  - `meetingDay`
  - `capacity`
  - `recruitmentDeadline`
  - `expectedDuration`
  - `conditions`
  - `leaderId`
- 모집글 수정 후 연결된 그룹 이름도 함께 수정할지 정책을 확정한다.
- 모집 종료, 수정, 신청 승인/거절 후 최신 상태를 바로 확인할 수 있도록 응답 또는 조회 API를 정리한다.
- 이미 가입한 그룹의 모집글에 참가 신청할 경우 `이미 참여 중인 그룹입니다`처럼 명확한 응답을 내려준다.
- 신청 승인 시 그룹원 추가가 정상 처리되었는지 응답 또는 후속 조회로 확인 가능해야 한다.

### Part3 그룹·일정

- 내 그룹 목록 조회 API는 구현 및 머지된 상태다.
- 그룹 홈 활성 그룹원 응답에 `nickname`, `profileImageUrl`이 포함되도록 수정된 상태다.
- 그룹 삭제를 허용할지, 종료 처리만 허용할지 정책을 확정한다.
- 그룹 홈에서 모집글 작성/관리 흐름과 그룹-모집글 연결 정책을 확정한다.
- 모집글 제목 수정 시 `study_groups.name`까지 동기화할지 결정한다.
- 일정 생성 후 일정 조회가 되지 않는 문제를 확인한다.
  - 생성 API 응답
  - 전체 일정 조회 조건
  - 다가오는 일정 조회 조건
  - 날짜 필터 기준
- 일정 목록 응답은 프론트가 일정 ID를 직접 노출하지 않고도 표시/선택할 수 있을 만큼 충분한 정보를 제공해야 한다.
  - 일정 ID
  - 일정 제목
  - 일정 일시
  - 장소 또는 온라인 링크
  - 내용
- 일반 MEMBER도 그룹 홈에서 본인 관련 일정, 참석 응답, 출석 상태를 조회할 수 있어야 한다.

### Part4 출석·활동

- 참석 응답 수정 기능이 필요하다.
- 출석 체크 수정 기능이 필요하다.
- 참석 응답 저장/수정을 하나의 API 또는 버튼으로 처리할지 결정한다.
- 출석 체크 저장/수정도 동일하게 정책을 정한다.
- 참석 현황 조회 API가 필요하다.
  - 일정별 참석/불참/미정 응답 수
  - 사용자별 응답 상태
- 개인 출석률 조회 API가 필요하다.
  - 일반 MEMBER가 본인의 출석률을 확인할 수 있어야 한다.
- 그룹장 또는 매니저는 그룹원별 출석 현황을 조회할 수 있어야 한다.
- 활동 회고 `activity_records`와 회고 리뷰 기능은 아직 미구현 상태로 보인다.

## 정책 결정 필요

- 그룹 삭제와 모집글 삭제를 실제 삭제로 허용할지, 종료 상태로만 관리할지 결정한다.
- 모집글 제목 수정 시 그룹 이름도 자동으로 바꿀지 결정한다.
- 모집글 작성 흐름을 확정한다.
  - 그룹 생성 후 모집글 작성
  - 모집글 작성 시 자동 그룹 생성
- 모집 종료 상태와 그룹 활동 종료 상태의 관계를 정의한다.
- 참석 응답은 마감 전까지 수정 가능하게 할지 결정한다.
- 출석 체크는 그룹장만 가능한지, 매니저도 가능한지 결정한다.
- 일반 MEMBER가 볼 수 있는 그룹 홈 범위를 정의한다.
  - 일정 조회
  - 본인 참석 응답
  - 본인 출석률
  - 활성 그룹원 목록
- 백오피스에서만 처리해야 하는 관리자 기능과 일반 서비스 화면에서 가능한 운영 기능을 구분한다.

## 우선순위

1. 모집글 상세 권한 문제 수정
   - 계정 전환 시 작성자 전용 버튼이 남는 문제
   - 작성자가 아닌 사용자의 참가 신청 버튼 미노출 문제
2. 모집 마감일 검증
3. 일정 생성 후 일정 조회 문제
4. 모집글 수정/종료/승인 후 상태와 메시지 갱신 문제
5. 참석 응답 수정 및 출석 체크 수정 기능
6. 일반 MEMBER용 그룹 홈 조회 범위 정리
7. 활동 회고 및 리뷰 기능 구현 여부 결정
