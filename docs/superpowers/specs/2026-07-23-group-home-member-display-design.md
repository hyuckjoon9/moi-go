# 그룹 홈 회원 표시 정보 설계

## 목표

`GET /api/groups/{groupId}`의 `members` 항목이 회원 식별자 대신 사람이 읽을 수 있는
표시 정보를 제공하도록 한다. 프론트엔드는 닉네임, 프로필 이미지, 그룹 역할을 표시한다.

## 응답 계약

기존 필드는 호환성을 위해 유지한다. 각 `members` 원소에 다음을 추가한다.

- `nickname`: 활성 회원의 닉네임
- `profileImageUrl`: 선택 프로필 이미지 URL이며, 설정되지 않은 경우 `null`

회원 정렬(역할, 가입 시각, 사용자 ID)은 변경하지 않는다.

## 구현 경계

이번 변경은 사용자 요청에 따라 `StudyGroupService`가 `MemberRepository`를 직접 읽는
예외를 둔다. 조회는 그룹 홈 응답 조립에 필요한 활성 그룹원의 닉네임과 프로필 이미지에
한정하고, 회원 Entity의 변경이나 회원 상태·권한 판단에는 사용하지 않는다.

활성 그룹원 ID를 한 번에 조회해 N+1 쿼리를 피하고, 조회 결과를 사용자 ID로 매핑한 뒤
기존 그룹원 정렬 순서를 보존해 DTO를 만든다. 활성 그룹원에 해당하는 회원이 조회되지
않으면 데이터 정합성 오류로 그룹 홈 조회를 실패시킨다. 임의의 표시명 대체값은 만들지
않는다.

## 테스트 및 문서

- 서비스 테스트로 닉네임, `null` 프로필 URL, 기존 정렬 및 다건 회원 조회를 검증한다.
- 그룹 홈 API 문서의 JSON 예시와 필드 설명을 갱신한다.
