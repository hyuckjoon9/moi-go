# Part 4 — 참석·출석·활동 기록

일정별 참석 응답과 출석, 출석률을 관리하고 활동 기록과 리뷰를 제공한다. Part3의 일정·그룹원·권한 계약을 사용해 그룹 범위와 접근 권한을 판단한다.

## 담당 기능

- 참석 여부 응답 등록·수정·삭제와 그룹원별 RSVP 현황 조회
- 출석 체크·정정·삭제, 개인·그룹 출석률과 자동 결석 처리
- 활동 기록 등록·수정·삭제·조회 및 활동 리뷰 작성·삭제·조회

## 주요 흐름

그룹원이 마감 전 참석 응답 → 일정 시작 후 운영진이 출석 체크 → 미체크 인원은 시작 2시간 후 자동 결석 처리 → 개인·그룹 출석률 집계 → 운영진이 활동 기록 작성 → 활성 그룹원이 리뷰를 남긴다.

## 제공 API와 내부 계약

- 출석 API는 `/api/attendance/**`에서 참석 응답, 출석 기록·요약, 개인·그룹 출석률을 제공한다.
- 활동 API는 `/api/activity/**`에서 일정별 활동 기록과 기록별 리뷰를 제공한다.
- 참석 응답은 Part3의 `ScheduleAttendancePolicyReader`로 일정·활성 그룹원·실질 마감을 확인하며, 그룹 출석률 권한은 `StudyGroupAttendanceRatePolicyReader`에 위임한다.

## 핵심 설계 및 처리 기준

- 참석 응답은 실질 마감 이전에만 등록·수정·삭제할 수 있다. 별도 마감이 없으면 일정 시작 시각이 마감이다.
- 활성 `LEADER`·`MANAGER`만 출석 현황·출석 체크와 그룹 출석률을 관리한다. 개인 출석률은 본인만 조회할 수 있다.
- 출석 신규 등록은 일정 시작 이후에만 가능하지만, 이미 있는 출석 기록의 정정은 시간 제한 없이 허용한다. 자동 처리도 중복 기록을 만들지 않도록 설계되어 있다.
- 활동 기록은 일정 시작 후 운영진이 작성하며, 활성 그룹원은 역할과 무관하게 조회·리뷰 작성 및 본인 리뷰 삭제를 할 수 있다.
- 일정 삭제 시 참석 응답은 `CASCADE`지만 출석·활동 기록은 `RESTRICT`이므로, 이력이 있는 일정은 Part3에서 삭제할 수 없다.

## 관련 파트

- Part1의 인증 principal에서 요청자·작성자·출석 확인자 ID를 받는다.
- Part3의 일정 식별자, 활성 그룹원 검증, 응답 마감 및 그룹 출석률 권한 계약을 사용한다.
- Part3의 일정 삭제 정책은 Part4 출석·활동 기록의 FK 보존 규칙과 함께 동작한다.
